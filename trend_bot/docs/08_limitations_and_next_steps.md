# 08. 既知の制約・未検証事項と、次の段階へ進むための条件

## 1. 既知の制約

### データ
- 先物の限月別実データが無い（取引所・ベンダーへの通信遮断）。成績はすべて代替データ（現物・指数・為替スポット）か合成データ。
- 代替データはキャリー・ロールイールド・配当−金利を含まない。特に NG・CL（コンタンゴ）、通貨（金利差）、国債（キャリー）で先物成績と乖離し得る。
- 日次代替に国債・金属・穀物・日欧株価指数が無く、2019 年以降は米国株も無い。最終評価期間（日次）は通貨とエネルギーだけ。
- 月次代替は平均値系列を含み（1 カ月の追加ラグで対処）、国債はデュレーション 6.5 仮定の利回り由来モデル。
- JPY 短期金利が無く、現金利息は 0（超過収益ベースの近似）。
- FX 代替データの README と実データの表記規約が食い違っていた（値域検査で検出し実データ側に合わせた）。

### 契約・コスト
- 18 市場すべての契約仕様（乗数・呼値・限月・最終取引日・第一通知日・取引時間）が一次資料で未確認。
- 手数料・スプレッド・証拠金・出来高は研究用仮定。証拠金は想定元本比の単純化で、SPAN 等のポートフォリオ証拠金・ブローカー上乗せ・円建て担保の掛け目は未反映。
- OSE（日経 225 mini、JGB）の休場判定は東証暦で代用。

### モデル・実装上の単純化
- 約定は t+1 清算値 ± コスト（寄付・VWAP・TAS 等の執行方法は未モデル化）。
- 部分約定、注文の取消・訂正の遅延、夜間セッションの帰属日処理は模擬ブローカーで単純化。
- 取引停止（halt）・値幅制限（limit）は当日約定不可として持ち越すのみ。制限値幅での部分約定は扱わない。
- 代替データの系列終了（S&P 日次 2018-12）時の手仕舞いは、系列終了日を事前に知っている扱い（バックテストのみ、データ終了の人工物）。
- ウォークフォワードは各候補の連続バックテストから年ごとに切替えており、切替時の建玉移行コストは含まない。
- 月末の円転判定・月末判定は取引日カレンダー（事前に知り得る情報）を使用。
- 模擬運用は毎日全履歴から再計算するため 1 サイクル数秒かかる（日次運用には十分だが、高頻度化は不可）。

## 2. 未検証事項

- 実先物での収益性・コスト・ロールの影響
- 日経 225・Euro Stoxx 50・Bund・JGB・Gilt・銅・穀物の日次での挙動
- 研究上の仮目標（超過 +3〜5pt、ボラ 8〜10%）の達成可能性。現状の実現ボラは約 5%
- 危機時の下支え効果（今回の代替データでは明確でない）
- 大口（10 億円）時の JGB 等大型契約・低出来高市場での執行可能性
- 実ブローカー API との接続、口座明細との照合、夜間処理のスケジュール運用
- 既存運用商品（公募投信・ETF 等）との参考比較（信頼できるデータと購入可能性を未確認のため未実施）

## 3. 次の段階へ進むための条件（Go/No-Go）

### 段階 2: 実データでの再検証（有料データ契約が必要）
開始条件:
1. 限月別の日次清算値・出来高・建玉（18 市場、少なくとも 2000 年以降）と限月カレンダーを `data/user/` の CSV 仕様で投入し、`trendbot quality --dataset real` で FAIL が無いこと
2. JPY 短期金利と参照為替レートの投入
3. 契約仕様を取引所一次資料で照合し `verification.status: verified`、確認日と URL を記録
4. 利用予定ブローカーの手数料・証拠金見積りで `assumptions.yaml` を置換（出所・日付を記録）

合格条件（**事前にここで固定**。実データの結果を見た後に変更しない）:
- 最終評価期間を除く期間の基準戦略で、コスト込み Sharpe ≥ 0.4、かつコスト×2 で ≥ 0.25
- 同ボラ換算で比較対象 B（株・債・金の定期リバランス）の超過収益を下回らない、または株式ポートフォリオへの 10〜20% 組入れで最大 DD と ES が改善
- 特定 1 市場除外・特定 1 年除外で Sharpe が 0.2 を下回らない
- 実データでの最終評価期間（2021 年以降、1 回のみ）で Sharpe > 0 かつ最大 DD が開発期間最大 DD の 1.5 倍以内
- PBO < 0.5（探索は事前登録範囲のみ）

### 段階 3: 実データでの模擬運用（紙上運用）
- 実データ配信（遅延の実測）で 3〜6 カ月以上の模擬運用を行い、バックテストとの乖離（約定価格・コスト・建玉）を日次で記録
- 障害訓練（本書 06 のシナリオ）を実データ環境で実施し、停止・照合・再開の手順を運用者が実行できること

### 段階 4: 少額の実資金（今回の対象外）
- `trendbot blockers` が 0 件
- ブローカー API アダプタの実装、第三者レビュー、秘密情報管理（環境変数/シークレットストア、コード・設定ファイルに書かない）
- 二重ロック（設定 `live_trading.enabled` と環境変数 `TRENDBOT_LIVE_TRADING`）の解除手順と承認者の決定
- 取引所・ブローカーのリスク管理（ポジション上限、キルスイッチ）の併用

## 4. 報告が必要な事項（利用者の判断・手配が必要）

| 事項 | 必要な判断・手配 |
|---|---|
| 先物限月別データの購入 | ベンダー選定・費用・再配布条件（02 §4） |
| ネットワーク許可 | 本環境で取引所・データ提供元へアクセスするには、環境設定のネットワークアクセスで該当ホストの許可が必要 |
| ブローカー | 口座・API 仕様・手数料と証拠金の見積り |
| 評価用の円短期金利系列 | どの系列を正とするか（TONA 等） |
| 既存株式資産の実際の構成 | 組入れ効果の評価に使う株式ポートフォリオの定義（今回は米国株・円換算・ヘッジなしで代用） |
| リスク許容度 | 目標ボラ・DD 縮小閾値・証拠金上限の最終値 |
