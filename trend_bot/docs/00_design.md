# 00. 設計書と実装計画（短縮版）

作成日: 2026-09-27 / 対象: 複数資産トレンド追随BOT（研究・バックテスト・模擬運用）

## 1. 環境確認の結果（2026-09-27 時点）

| 項目 | 結果 |
|---|---|
| リポジトリ | Next.js boilerplate（取引関連の既存コード・指示ファイルなし）。本BOTは `trend_bot/` 以下に Python で独立実装し、既存 Next.js には手を入れない |

| 代替データ | GitHub 上の公開再配布（FRED H.10 為替、EIA 原油・天然ガス現物、Shiller S&P 月次、World Bank 金 月次、Fed H.15 米10年利回り 月次、IMF 商品価格 月次）と `arch` 同梱データ（S&P500 日次 1999–2018、Fama-French 月次）|

## 2. データの三区分（すべての成果物に明示する）

| 区分 | 用途 | 表示ラベル |
|---|---|---|
| 実データ（先物限月別） | 本番判断・運用可否判定 | `REAL_FUTURES` — **今回は存在しない** |
| 代替データ（現物・指数・為替スポット） | 戦略ロジックの予備検証 | `PROXY_PRELIMINARY`（予備検証）|
| 合成データ | ソフトウェアの動作確認専用。成績は一切の意味を持たない | `SYNTHETIC_TEST_ONLY` |

## 3. モジュール構成（責務分離）

```
trend_bot/
  config/            設定（戦略・銘柄仕様・研究用仮定・探索範囲・模擬運用・データ出所）
  src/trendbot/
    config.py        設定読込・検証・ハッシュ
    contracts.py     銘柄仕様・検証状態・本番阻害条件
    data/            取得(fetch_public)・CSV仕様(schema)・読込(loaders)・品質検査(quality)・合成(synthetic)・暦(calendars)
    continuous.py    限月選択（時点整合）・連続系列（シグナル専用）
    signals.py       トレンドシグナル
    riskmodel.py     ボラティリティ・相関推定
    portfolio.py     目標建玉（リスク予算・分散乗数）
    risk.py          リスク上限・整数化後の上限再検査・DD縮小・停止判定
    execution.py     注文生成（バッファ・変更量上限・流動性上限）・コスト・約定
    accounting.py    多通貨台帳（値洗い・利息・為替換算・損益寄与）
    strategy.py      バックテストと模擬運用で共有する判断コア
    backtest.py      日次イベントループ
    benchmarks.py    比較対象 A/B/C
    metrics.py       評価指標
    evaluation/      ウォークフォワード・PBO・ストレス・頑健性・容量
    paper/           ブローカーIF（模擬/本番スタブ=無効）・状態DB・日次サイクル・照合
    report/          HTML ダッシュボード
    manifest.py      実行記録（コード版・設定ハッシュ・データハッシュ・乱数種）
    logutil.py       構造化ログ(JSON Lines)
```

## 4. 時刻と約定の約束事（詳細は 01_strategy_spec.md）

- 判断：各市場の日 t の清算値確定後（運用上は翌営業日 JST 07:00 の一括判断）
- 発注：日 t+1 の取引セッション
- 約定価格の仮定：日 t+1 の清算値 ± コスト（片側スプレッド＋インパクト＋手数料）。**同日終値での約定は仮定しない**
- 遅延ストレス：t+2 約定

## 5. 実装計画（実施順）

1. 設定・銘柄仕様・データ層（CSV仕様、代替データ取得、合成データ、品質検査）
2. 連続系列・シグナル・ポートフォリオ・リスク・注文・会計・バックテスト（合成データで全経路を通す）
3. 先物固有の検証テスト（未来情報、乗り換え、値洗い、為替、負価格、上限、重複注文）
4. 比較検証（A/B/C/D）、ウォークフォワード、PBO、感度、除外、ストレス、容量
5. 模擬運用（状態DB、照合、停止・再開、障害注入）
6. レポート・ダッシュボード・手順書・引き継ぎ

## 6. 主要な設計判断（自分で決めて記録したもの）

| 判断 | 理由 |
|---|---|
| 価格「差」ベースでボラ・トレンドを計算 | 負価格・ゼロ近傍でも破綻しない。加算型バックアジャストと整合 |
| 連続系列は保有限月の日次価格差の累積として構築 | 乗り換え時の限月間価格差を損益・シグナルに混入させない。過去値の再調整が差分を変えないため未来情報が入らない |
| 損益は実限月の清算値の差 × 乗数 × 枚数 | シグナル用系列と損益用価格を分離 |
| 相関は週次（5営業日合計）で推定 | 市場ごとの終了時刻差（東京/欧州/米国）による日次相関の過小評価を緩和 |
| リスクを増やす方向にのみ変更量上限・流動性上限・バッファを適用、上限超過の解消は優先 | 障害時・急変時に建玉が意図せず増えないことを優先 |
| 目標ボラ未達時の自動増量はしない（上限超過時の縮小のみ） | 逆ボラ一辺倒の増量を避ける |
| 停止時の既存建玉は原則維持、証拠金不足時のみ縮小計画（既定は手動承認） | 機械的な全決済が安全とは限らない |
| 本番発注は二重ロック（設定＋環境変数）＋実装スタブで常に無効 | 今回の範囲外 |
